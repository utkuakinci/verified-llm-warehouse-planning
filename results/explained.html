The project in plain English

No background in planning or machine learning is needed. Every number here comes from the recorded runs behind the full report.

In short

A small AI model writes plans for warehouse robots. A strict program, which knows the rules exactly, checks each plan step by step. If a plan is wrong, the reason goes back to the model and it tries to fix the plan.

The main question: how much better is it to tell the model why a plan is wrong, compared with just letting it try again?

  • With the Qwen3-4B model, 10% of first attempts were valid. Telling it the reason raised that to 26.7%. Letting it retry without the reason left it at 10%.
  • With a much weaker model, Qwen2.5-1.5B, telling it the reason changed nothing.
  • The largest single jump came from briefly training that weak model on correct plans: 0% to 36.7% on the first attempt.
  • The two methods did not add up. On maps it had trained on, the trained model did worse with the reason than without it.

The problem: a warehouse

The warehouse is a grid, and a robot can only move to a neighbouring cell. This is the map of the easiest level:

a00a10a20a30a40 a01shelf1a21shelf2a41 a02a12a22a32a42 station1station2

Shelves are entered from the left or right. Stations are entered only from the aisle cell above them. Robots have three actions:

ActionWhat it doesWhat it needs
moveGoes to a neighbouring cellThe cells are neighbours and the target is empty
pickTakes an item from a shelfThe robot is at that shelf, the item is there, and the robot carries nothing
dropLeaves an item at a stationThe robot is at that station and carries the item

A cell holds one robot and a robot carries one item, so with several robots they can block each other. There are 30 problems across six levels:

Plans are written in PDDL, a standard language for planning problems. This real 7-step plan carries one item on the map above:

(move robot1 a21 shelf2)        go to the shelf
(pick robot1 item1 shelf2)      take the item
(move robot1 shelf2 a21)        back to the aisle

The parts of the system

PartJobThink of it as
Language model (Qwen)Writes the planAn intern
Validator (unified-planning)Checks the plan step by step and reports the first error and its causeAn inspector
Fast DownwardFinds the shortest plan by itself, so the model's plans can be measured against itThe answer key
Blind retriesGets the same number of tries but never sees the reasonThe placebo group in a drug trial
LoRABriefly trains the model on verified plansA short course for the intern

If Fast Downward finds the shortest plan, why use a language model? In this small warehouse the classical planner is clearly better: it solves all 30 problems and finds the shortest plan each time. The project does not claim otherwise. It builds the loop where a model generates, a strict program verifies and the model learns from the error, and it measures what that loop actually gains.

One run, step by step

This is a real recorded run with 2 robots and 3 items, where the shortest plan has 28 steps.

  1. The model writes a plan. Each line is checked as soon as it is written, because nothing after the first wrong line can be used. Writing stops at line 37.
  2. The validator finds the error. The first 36 steps are fine. Step 37 tries to enter a cell that is not a neighbour: 
    Step 37: (move robot1 a33 station1) cannot be executed.
Unsatisfied precondition: (connected a33 station1).
From a33, robot1 can move to: a23, a43, station2.
station1 can only be entered from: a13.
  3. The correct steps are locked. The first 36 steps are kept and cannot change.
  4. The model gets a new question. It does not see its failed plan. It sees the situation those 36 steps reached, as a new and smaller problem, plus the reason for the rejection. Shown its own plan, the model mostly wrote the same plan again.
  5. The model writes the rest. Here it needs only four lines: 
    (move robot1 a33 a23)
(move robot1 a23 a13)
(move robot1 a13 station1)
(drop robot1 item3 station1)
  6. The whole plan is checked again. All 40 steps are valid. That is 1.43 times the shortest plan, because locked steps cannot be taken back.
  7. If it is still wrong, the loop continues, for at most 4 repair rounds in total.

Why there are two arms

Give a model five tries and it may succeed by luck, even if it learns nothing. So every problem runs twice, as in a controlled experiment:

  • Feedback arm: sees the reason and continues from where the plan stopped.
  • Blind arm: gets the original question again and never sees the reason.

Both share the same first attempt and the same number of tries. The gap between them is the value of the information, not of trying more than once.

What came out

Share of runs that ended in a valid plan, on 30 problems with up to 4 retries.
ModelFirst attemptWith the reasonBlind retries
Qwen3-4B10.0%26.7%10.0%
Qwen2.5-1.5B0.0%0.0%3.3%
Qwen2.5-1.5B after LoRA training36.7%43.3%56.7%
  • The reason helps a model that is already close. On Qwen3-4B the gap is 16.7 points. Taking chance into account, it is likely between 5 and 30 points, so it is unlikely to be luck.
  • It does not help a model that is not. Qwen2.5-1.5B wrote no valid plan in 90 first attempts.
  • The gain is on the easy levels. On levels 3 to 6, where several robots share the map, 1 run of 40 was solved.
  • Training did more than the reason did. The small model rose from 0% to 36.7% on the first attempt, ahead of the larger model.
  • The two do not add up. On known maps the trained model did 13.3 points worse with the reason. One possible cause is that it trained only on plans from the start, while a repair begins mid-plan. That explanation has not been tested.
  • Valid plans are close to the shortest. Qwen3-4B's valid plans were 1.11 times the shortest on average, measured on solved runs, which are mostly easy problems.

The test problems share their maps with the training problems, so the models also ran on wider maps that no prompt or training example shows. The trained model dropped there, from 11 to 4 valid first attempts out of 20, but the untrained Qwen3-4B dropped too, because those problems are harder. The trained model was still the best of the three.

What to keep in mind

  • 30 problems is a small sample, so the numbers are estimates with wide margins.
  • Training used Fast Downward's plans, not the model's own, because the untrained model wrote too few valid plans. So this shows learning from verified plans. It is not a closed self-improving loop.
  • Prompts were tuned on separate practice problems using the small model and then frozen, so Qwen3-4B ran with prompts not tuned for it.
  • Claude was not compared because no API key was available, and Llama 3.2 1B was not tested because access to the model is restricted.
